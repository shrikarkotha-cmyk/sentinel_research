# V0.8.2: Standalone Windows activation and offline relaunch

## Objective
Assess whether an original Sentinel-protected graphical game can be distributed as a standalone Windows package and relaunched without the activation service or an internet connection after initial enrollment.

## Method and observations
On November 24, 2026, a GitHub-hosted Windows x64 build compiled the prototype, passed both native CTest checks, and packaged the launcher. A second successful build used a public issuer key generated locally by the researcher. The private signing key remained on the developer computer. The researcher extracted the player package, opened the launcher, ran the local synthetic-account issuer, and activated the game. A screenshot showed the graphical game window running. The researcher subsequently reported that the game relaunched successfully after closing the game, launcher and issuer and disconnecting from the internet, following the supplied test procedure.

## Result
One researcher-reported physical Windows offline relaunch succeeded. The graphical window was observed in a screenshot before the offline test. The offline result is self-reported; no independent network capture or repeated measurements were collected. The developer computer already had development tools installed, so a clean machine with no development tools remains untested.

## Limits and next steps
This pilot supports the feasibility of offline authorization in the tested configuration. It does not establish indefinite reliability, resistance to professional cracking, physical cross-device copy resistance, or performance under commercial launch traffic. Repeat the offline procedure, record network isolation and provider type, compare protected and baseline performance, and conduct bounded synthetic scalability experiments on an isolated owned service.

Development and documentation were AI-assisted. No private keys, activation codes, personal screenshots or identifiers are published in this report.
