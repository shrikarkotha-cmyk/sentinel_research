# V0.15 candidate: Vault and release-signing foundation

## Objective
Strengthen the local developer and issuer trust boundary before further runtime protection or Adaptive research. Starfall Trail remains an internal workbench. The native runtime and offline license protocol are unchanged.

## Implemented
The local Vault module validates existing Ed25519 PEM files, refuses malformed or missing existing keys rather than silently replacing them, checks POSIX owner-only permissions and publishes explicitly initialized keys via a private temporary file and no-replace hard link. Release and issuer keys must be distinct. Only the issuer admin init command may generate an issuer key; ordinary reads and grant operations require existing keys. Packaging checks the signing key against the configured public-key header, checks role separation, and hashes files in 1 MiB chunks. No new player launch or network requirement was added.

## Observed
11/11 new Vault and package unit tests passed, including eight concurrent setup calls converging on one key, stable reuse, rejected missing/corrupt/wrong-type keys, POSIX mode check, role separation, mismatched and valid signing configurations, and streaming hash equivalence. Nine existing device-bound enrollment checks passed. Two clean Linux builds each passed both native tests. The first integration run passed 74/74 with GUI checks; the second enabled both GUI and OpenGL checks and passed 78/78, matching the set of V0.14 regression case names. The result count includes the explicitly expected software credential cloning and offline refund limitations. OpenGL used llvmpipe, not a physical GPU. The 61-file source archive passed ZIP CRC verification and contained no PEM or generated key header.

## Limitations
This is a local lab key lifecycle module, not an HSM or production vault. The trusted developer filesystem must support hard links; Windows ACL enforcement, macOS and Windows runtime validation, encryption at rest, key rotation, backup/restore drills and production access controls remain pending. Packaging validates the header, not proof of a binary's embedded public keys; clean rebuilds are required after key changes. Native runtime version remains 0.12.0; V0.15 denotes the candidate source and test report. No new burst throughput measurement or stronger runtime anti-tamper claim is made. The verifier-intact integrity results are regressions, not evidence of professional binary tamper resistance. No real storefront or production signing secrets were involved.

## Next gate
Validate recovery and protected device storage on distinct physical computers, test issuer backup and recovery using disposable credentials, and evaluate independent release integrity and compatibility. Keep the separate player-impact disclaimer. Independent reproduction is required.
