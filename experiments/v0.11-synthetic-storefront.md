# V0.11: Synthetic storefront transaction pilot

Status: Linux sandbox tested; Windows storefront GUI and packaged player integration pending.

## Purpose
Evaluate storefront ownership, automatic first authorization, refund and repurchase independently from possession of downloaded files, without real payments or third-party storefront access. Starfall Trail remains an internal workload, not a commercial game.

## Implementation
A developer-only local store records zero-dollar purchases and refunds in a SQLite transaction ledger, separates ownership from device-bound offline authorization, and provisions short-lived enrollment grants for automatic first launch. Refund withdraws ownership and invalidates outstanding grants. Named test profiles preserve existing licenses and saves while simulating fresh installations. The private issuer remains local; the player package requires no signing secrets or developer tools. The UI uses synthetic accounts and binds its service to loopback only.

## Observed results
The disposable Linux build passed 2/2 native tests and 63/63 expected integration outcomes, including ten added transaction cases. The new checks demonstrated denial of a grant without purchase, zero-cost ownership acquisition, idempotent replay of a transaction, automatic authorization and graphical quest completion, refund recording, denial of pending grants after refund, continued launch using an existing offline license after refund, repurchase and successful fresh activation, denial after refund before first Play, and launch after issuer shutdown. The earlier OpenGL workloads and negative checks also ran. The native engine is derived from V0.10; the original test report version tag remains 0.10.0.

## Limitations
Indefinite offline licenses cannot be immediately revoked by a server-side refund, and portable software credential cloning remains a known weakness. The test count includes expected limitations. No actual Steam integration, payment, production scale measurement, Windows GUI test, or commercial cracking assessment was performed. A successful local synthetic transaction is not payment evidence. The V0.11 source package and private workflow were prepared; Windows compilation requires source import and a manually triggered build. The larger-game GPU and 50,000-player activation experiments remain separate research tasks.

Development and documentation were AI-assisted; independent reproduction is required before academic submission.
