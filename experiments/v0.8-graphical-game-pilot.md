# Sentinel V0.8: Graphical game pilot

## Objective
Evaluate the existing licensing and integrity controls on a more complex, original graphical game, rather than only a text adventure.

## Implementation
The original console quest was retained. A new native C++ isometric exploration mode uses a 24 by 24 tile map and 11 original cuboid model types. It supports keyboard movement, collision, NPC interaction, inventory, resource collection, crafting, a beacon quest, and local save/load. Both modes use the existing local authorization and signed-manifest verification. Model data is required in the manifest. Linux X11 window support was exercised; Windows GDI support is included but untested. No macOS native window backend has been implemented.

## Method
Fresh disposable Linux source build, GNU C++ 14.2.0, OpenSSL 3.5.7, synthetic signing credentials, loopback activation service and independent simulated profiles. The service was stopped during the offline tests. GUI smoke tests ran in Xvfb. Tests target only the original demo and synthetic entitlements.

## Observations
- Two native tests passed. All 45 integration outcomes matched expectations, including known security gaps; this is not 45 defeated attacks. All 35 earlier integration outcomes were reproduced.
- The headless graphical quest completed in 47 movement steps, including crafting, save/load and beacon restoration. The native window appeared, accepted keyboard movement and save input, and exited cleanly.
- Missing authorization, changed signed models and changed executable bytes were rejected by the intact verifier.
- The complete portable software credential-copy weakness was reproduced in the graphical game. The copied profile completed the quest. Existing offline licenses also remained usable after ownership withdrawal, as designed.
- One sample of 60 CPU-rendered frames took 19.861 ms. This is not display FPS or a measurement of DRM overhead because no equivalent unprotected comparison was performed.

## Interpretation and limitations
A larger gameplay workload enables more representative integrity, compatibility and performance experiments; it does not inherently strengthen the authorization gate. No full reverse-engineering assessment, professional time-to-break measurement, physical Windows TPM test, or comparison with Denuvo was performed. Changes to the verifier itself remain outside the demonstrated resistance of the prototype. The next research priorities are controlled baseline comparisons, physical-device testing and documented recovery and mod behavior.

Development, testing automation and documentation were AI-assisted. The researcher should independently reproduce and interpret the results before using them in an academic submission. No raw credentials or private source code are included in this report.
