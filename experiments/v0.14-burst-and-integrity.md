# V0.14 candidate: simultaneous-arrival burst and integrity regressions

## Scope and method

The V0.13 device-bound grant candidate was the baseline. V0.14 changes only the issuer service: initialize schema once, load its Ed25519 signing key once per service identity, use SQLite WAL with FULL synchronization, and explicitly close request connections. Key rotation requires restart; the cached key remains resident in service memory. Authorization decisions, grant redemption and audit records remain transactional. This is isolated lab infrastructure, not a public production service.

For each variant, the same 50,000 synthetic requests and copied initial database became eligible at one logical instant, serviced by four in-process workers. There were 40,000 legitimate requests, 5,000 unowned accounts and 5,000 invalid device proofs. No sockets, external endpoints, real players or real storefronts were involved. One matched run per variant, baseline first. Aggregate throughput includes independent license signature and field verification. Handler latency excludes backlog; arrival-to-response includes it.

## Observed results

| Metric | V0.13 baseline | V0.14 candidate |
| --- | ---: | ---: |
| Requests | 50,000 | 50,000 |
| Elapsed seconds | 90.309 | 51.408 |
| Requests/second | 553.66 | 972.62 |
| Handler p50 ms | 1.723 | 0.907 |
| Handler p95 ms | 10.361 | 9.640 |
| Handler p99 ms | 106.496 | 54.913 |
| Arrival-to-response p50 seconds | 46.863 | 25.995 |
| Arrival-to-response p95 seconds | 86.246 | 47.524 |
| Incorrect decisions | 0 | 0 |

Each run issued 40,000 valid licenses, rejected 10,000 invalid requests, and passed verification of every issued license. Both databases retained 40,000 device records, 40,000 consumed grants, 5,000 unused grants, 45,000 purchases, 135,000 audit records, and an integrity check of ok. Throughput increased by approximately 75.7%, and total processing time decreased by 43.1%.

A separate single-worker profile of 500 legitimate activations per variant recorded 500 schema executescript calls and 500 PEM loads in the baseline request loop, neither present in the optimized request loop. SQLite commit remained the largest measured individual cost (approximately 1.02 s baseline and 0.50 s candidate across the samples). Profiling ran alongside other regression work; timings are diagnostic, not a controlled independent replication. The changes were bundled, so the individual contribution of each change is not isolated.

## Integrity and authorization regression

A clean Linux build passed 2/2 native CTest checks and 78/78 expected integration and GUI outcomes. A separate nine-check bound-grant pilot also passed. Added integrity cases rejected missing and truncated protected world assets and a changed security-library file with verifier behavior intact. Existing negative cases rejected altered signed licenses, manifests, protected models, terrain materials, device helpers and game executable bytes. Approved mods, restored installation, offline gameplay and graphical workloads continued working. Software credential cloning still succeeded as an explicitly expected known limitation; test counts include such outcomes. A withdrawn entitlement cannot immediately invalidate a previously issued indefinite offline license.

## Interpretation and limitations

This is a simultaneous-arrival workload, not 50,000 simultaneous network connections, a production TLS/service capacity test, or 50,000 game instances. One run per variant cannot establish repeatability or production scalability. The optimized queue still imposes a roughly 26-second median wait. The integrity checks demonstrate detection of unauthorized file changes when the verifier remains intact, not resistance to disabling the verifier, professional reverse engineering, or Denuvo-equivalent anti-tamper. Windows compilation, hardware-backed device testing, controlled DRM overhead and independent review remain pending. Next steps: repeated matched tests, database architecture evaluation, bounded network testing only in a separately authorized lab, recovery testing and independent assessment of runtime protection. Independent researcher reproduction remains necessary.
