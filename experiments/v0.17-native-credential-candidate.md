# V0.17: Native credential provider candidate

Implemented a shared credential selection layer in the existing native SDK. It preserves existing TPM and software references, rejects conflicting credentials, and requires recovery when an already-licensed profile lacks a credential. The Windows adapter retains TPM support and proposes DPAPI fallback for recognized provider-unavailable errors on fresh profiles. An initial Apple Silicon Secure Enclave adapter uses Security.framework and P-256 signatures, storing a local lookup tag instead of exporting a private key. Linux and Intel Mac software fallback remains unchanged.

## Observed results
A disposable Linux build passed 3/3 native CTest groups, including nine provider-selection assertions, and 77/77 expected integration and X11 GUI outcomes. Four optional OpenGL cases were not enabled. A separate 16/16 synthetic recovery policy test passed. The archive passed CRC checks and contained no private PEM signing keys. Counts include expected limitations.

## Limitations
Windows and macOS native compilation and physical testing have not been performed. The Windows provider-open probe does not guarantee TPM key creation availability. Mac signing, Keychain access across executables, concurrent initialization and actual hardware recovery require testing. Intel T2 and Linux TPM hardware providers, SteamOS and Proton remain pending. Provider labels are not hardware attestation. No automatic real storefront recovery, stronger runtime anti-tamper claim, or new performance measurements are made. Software cloning and indefinite offline refund limitations remain. The build kit is source, not an installable release. Starfall Trail remains an internal workbench. Independent reproduction remains necessary.
