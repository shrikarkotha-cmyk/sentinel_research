# V0.9: Textured workload and simulated storefront pilot

Status: Linux sandbox tested; Windows build pending.

## Objective
Increase the original game's asset and animated rendering workload and reduce legitimate first-launch friction, without removing offline authorization or supported mods.

## Implementation
Eight original 2048 by 2048 RGB terrain materials are generated at build time, totaling 100,663,296 bytes. The renderer loads and samples these materials; they are not inert padding. Additional cuboid and pyramid geometry, vegetation, animated foliage and collectibles extend the isometric CPU renderer. The observed uncompressed Linux release totals 100,927,449 bytes. This is not a GPU-powered commercial 3D engine.

The simulated storefront provisions a short-lived, single-use grant to the player profile. A player with no existing license can press Play to request authorization without entering a code. The native verifier checks the issued signed license. Existing licenses are verified locally and do not require the issuer. Manual activation remains a lab option. The developer-operated issuer stays separate; this is not real Steamworks integration.

## Results
Linux native tests passed 2/2. Integration and X11 window checks matched 51/51 expected outcomes, including known limitations. Automatic authorization with a valid synthetic grant, rejection of a false handoff, offline relaunch, altered terrain material rejection, quest completion, keyboard input, saving, and clean window exit were observed. The one-click authorization backend was exercised directly; the revised Windows launcher interface and physical Windows behavior remain unverified. The portable software credential clone still succeeded.

One 60-frame CPU rendering workload took 109.325 ms. This is neither measured display FPS nor a controlled measure of licensing overhead. An equivalent unprotected build and repeated matched measurements remain necessary.

## Next steps
Import the source-only V0.9 build kit into the private engine repository, run the prepared Windows build, and test fresh-profile automatic activation and existing-license relaunch. Expand toward a GPU-rendered workload, compare matched protection conditions, and evaluate bounded synthetic activation load. No private signing keys or generated licenses are included in the source kit. Independent researcher replication remains necessary.
