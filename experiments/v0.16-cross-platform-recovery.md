# V0.16 candidate: cross-platform credential and recovery foundation

## Objective
Make the SDK and authorization protocol portable across operating systems, with low-friction recovery and explicit distinctions between hardware-backed and software credentials. Starfall Trail remains an internal research workbench.

## Implemented
The new additive C ABI provider diagnostic reports the available local credential provider without creating or replacing keys. This is local diagnostic information, not hardware attestation. A new trusted-admin recovery operation requires an explicit database transaction, current synthetic ownership, a prior enrollment and a specified replacement public key and algorithm. It supersedes unused recovery grants for the same account/game transactionally, without revoking existing offline licenses. The legacy lab recovery flow remains available; no production remote recovery endpoint, automatic recovery UI, or real storefront authentication was implemented.

## Measured results
16/16 targeted synthetic recovery checks passed, including Ed25519-to-P-256 replacement, signed identity fields, invalid replacement rejection, superseded and redeemed grant denial, refund denial, preservation of prior device records and database integrity. A separate clean Linux build passed 2/2 native tests and 81/81 integration and graphical outcomes. Native recovery used a distinct software profile; OpenGL ran on Mesa llvmpipe. The test counts include known offline refund and portable credential-cloning limitations. No physical hardware-backed proof, Valve integration, Windows or macOS build was tested in this change.

## Platform architecture and release gates
Use a single C-compatible SDK and signed license protocol. Existing Windows CNG TPM adapter remains unchanged; current initialization requires TPM and refuses existing legacy software keys. A supported non-TPM path and safe migration are still needed. macOS and Linux currently use the exportable lab software provider. Proposed native providers are Apple Secure Enclave P-256/Keychain and Linux TPM 2.0/OS credential storage; SteamOS and Proton require distinct validation. Do not infer physical hardware provenance from P-256 signatures or local provider labels. Hardware loss recovery should reverify storefront ownership and enroll a replacement credential, retaining saves and valid licenses until replacement is verified. Previously issued disconnected licenses cannot be immediately revoked. Test on real Windows, Apple Silicon, Linux and Steam Deck configurations; measure startup, recovery, compatibility, and player-facing costs. No claim of universal compatibility, Valve endorsement, or commercial tamper resistance.
