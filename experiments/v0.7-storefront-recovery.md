# Sentinel V0.7: Storefront entitlement and recovery pilot

## Objective
Separate synthetic ownership, device enrollment, and offline authorization. Preserve existing signed licenses, mod compatibility, and portable regression tests.

## Implementation
A simulated storefront provider checks ownership independently of device enrollment. Single-use enrollment and administrator-approved recovery grants expire after ten minutes by default. SQLite transactions protect grant consumption and issuance records. Local audit records document authorization decisions. The Windows TPM provider remains unchanged; portable software keys are weaker. No real Steamworks connection exists.

## Observed results
A disposable Linux source build completed successfully. CTest reported 2/2 passing native tests; 35/35 integration checks matched their expected outcomes, up from 27 in V0.6. New checks cover approved recovery, original-device access after recovery, separate enrollment records, ownership withdrawal, expired grants, missing ownership, and audit records. Previously established license, manifest, supported mod, and gameplay regression tests passed again.

Two expected outcomes demonstrate limitations rather than security improvements: an already issued unlimited offline license remains valid after ownership withdrawal, and complete portable software credentials can still be copied. These findings must not be reported as successful prevention of piracy.

## Limits and next steps
Real Steamworks authorization, Windows compilation, physical TPM behavior, production recovery identity proof, hardware attestation, commercial anti-tamper resistance, graphical performance, and autonomous adaptation remain unverified or unimplemented. The local HTTP lab is not a production service. Use only synthetic accounts and owned test applications. Next, improve reproducibility, review recovery policy, and measure startup overhead against an equivalent baseline.
